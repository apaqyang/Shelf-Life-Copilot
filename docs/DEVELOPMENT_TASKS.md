## 1. 使用方法

状态：

- `[ ]` 未开始或正在进行。
- `[x]` 已完成并通过验收。
- `BLOCKED` 必须在任务文字中写明外部依赖。

优先级：

- `P0`：生产安全、数据正确性或基础迁移的前置条件。
- `P1`：完成主业务闭环所需的能力。
- `P2`：规模化、开发体验或较低风险的改进。

任务完成时应在同一变更中勾选，并附上对应测试、文档或迁移结果。

## 3. P0 · 生产加固

### 数据与迁移

- [x] `DATA-101` 为 SQLite schema 增加版本表和迁移执行器。
  验收：新库可一次初始化；旧库可重复升级；升级失败不留半完成 schema。
- [x] `DATA-102` 为 DecisionStore 和 SuggestionStore 定义持久化 protocol 及共享契约测试。
  验收：SQLite 实现通过契约测试；业务层不导入 `sqlite3`。
- [x] `DATA-103` 定义数据库连接关闭、并发访问与 busy timeout 策略。
  验收：多线程并发写入测试通过；FastAPI lifespan 退出后连接被关闭。

### 回调与 API 安全

- [x] `SEC-101` 在非开发环境禁止启用明文企微回调。
  验收：生产环境缺少安全回调 adapter 时启动失败；本地模式仍可自测。
- [x] `SEC-102` 为回调事件增加幂等键、重放时间窗和去重存储。
  验收：同一事件重复投递只产生一条决策；过期事件被拒绝并留日志。
- [x] `SEC-103` 为 webhook 和手动触发 API 增加请求大小限制与限流。
  验收：超限请求返回明确错误；正常扫描不受影响。
- [x] `API-101` 实现经认证的手动扫描 API，复用 `ScanRunner`。
  验收：接口不复制扫描逻辑；返回每批次成功/失败摘要；有鉴权和幂等测试。

### 可观测性与运行可靠性

- [x] `OBS-101` 统一结构化日志字段。
  验收：扫描、建议、推送、回调和报告日志均包含 `customer_id`、`correlation_id`、结果与耗时。
- [x] `OBS-102` 增加最小运行指标集。
  验收：可观测扫描成功率、LLM 延迟、推送失败、回调处理数和报告生成结果。
- [x] `OPS-101` 编写 SQLite 备份/恢复与发布回滚手册。
  验收：临时环境中完成一次备份、删库后恢复和版本回退演练。

## 9. Definition of Done

每个任务只有在同时满足以下条件时才能勾选：

1. 行为和边界已用自动化测试固定，缺陷修复先有失败回归测试。
2. `ruff check`、`ruff format --check`、`mypy` 和相关 `pytest` 全部通过。
3. 数据迁移、配置变更和外部接口具有向后兼容或明确的升级说明。
4. 日志不包含凭据、原始库存载荷或不必要的个人信息。
5. 对外行为、目标架构或运维方式变化时，相关文档同步更新。
6. `git status` 中没有任务外的文件变更，内容边界检查通过。
